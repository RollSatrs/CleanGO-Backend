# CleanGo: архив и безопасное хранение заказов

## Реализовано
- `GET /orders/history?section=active|archive&page=N` — только подтверждённый клиент, только собственные заказы, 20 записей на страницу, сортировка по `created_at DESC, id DESC`.
- Активные: все статусы, кроме терминальных. Архив: `completed`, `cancelled`, `unassigned`, `expired`, `failed`, `no_cleaner`.
- Архив — **логическое представление**, не перенос и не удаление строк. `GET /orders` сохранён для совместимости с отслеживанием заказов.
- Запросы истории не требуют миграций и не изменяют данные.

## Политика тестовых данных (план, НЕ включена)
1. Добавить явно контролируемую классификацию `orders.is_test` с `NOT NULL DEFAULT false` (или отдельный `environment`/источник). Нельзя определять тестовый заказ по имени, цене, адресу, номеру телефона или дате.
2. Существующие заказы **не считать тестовыми автоматически**. Для них потребуется ручная маркировка с аудитом и подтверждением владельца.
3. При создании тестовых заказов использовать только доверенный административный/тестовый механизм; публичный клиент не может самостоятельно маркировать коммерческий заказ как тестовый.
4. После добавления классификации и резервной копии: dry-run со списком ID и количеством кандидатов; отбирать только `is_test = true`, терминальные статусы и возраст >30 дней. Не затрагивать активные заказы.
5. Удаление выполнять транзакционно, учитывая FK `order_offers` и `order_events`, с журналом операции и ограничением размера пакета. Убедиться, что нет оплат, споров или финансовых обязательств.
6. Включать автоматическое удаление только отдельным решением после проверки на тестовой БД и подтверждения политики хранения.

**Сейчас автоматическое удаление отключено, существующие записи сохраняются.**
